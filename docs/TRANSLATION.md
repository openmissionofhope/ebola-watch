# Translation guide

The dashboard is available in English (the source), French, Swahili, Lingala,
Portuguese and Arabic, and since October 2026 in Hausa, Yoruba and Igbo
(Nigeria), Amharic and Afaan Oromoo (Ethiopia), Luganda (Uganda) and
Kinyarwanda (Rwanda). Readers choose a language at the top of every page; the
choice is remembered in their browser, and a link can select one with
`?lang=fr`. Browsers can translate the site into other languages (see the
*Languages* page); the dashboard is built to survive that without breaking and
keeps figures out of machine translation (`translate="no"`).

**Status.** All non-English catalogs were produced with machine assistance and
have **not yet been reviewed by native speakers**. Until a language is marked
reviewed, every page shows a notice saying so, with a link to the English
version. Medical-scope wording (the "not a medical service" notice) matters
most: please check it first.

## Where the text lives

| File | Contents |
|---|---|
| `frontend/src/i18n/ui.en.json` | every interface string (generated: `npm run i18n:extract`) |
| `frontend/src/i18n/server.en.json` | templates of sentences generated by the backend (severity explanations, model notes, alerts, report lines), each with a note for translators |
| `frontend/src/i18n/locales/<code>.json` | one catalog per language |
| `frontend/src/i18n/index.tsx` | the list of languages and their review status |

A catalog looks like this:

```json
{
  "_meta": {"language": "fr", "name": "Français", "status": "machine-assisted", "glossary": {"confirmed case": "cas confirmé"}},
  "ui": {"Overview": "Vue d'ensemble", "Data as of {date}": "Données au {date}"},
  "server": {"{n1} confirmed cases reported in the last {n2} days (threshold {n3}).": "{n1} cas confirmés signalés au cours des {n2} derniers jours (seuil {n3})."},
  "places": {"COD": "République démocratique du Congo"}
}
```

Rules for translators:

* Keep every placeholder exactly as written (`{date}`, `{n1}`, `{t2}` …); you
  may move it within the sentence. `{n…}` is a number and `{d…}` a date (both
  are formatted for the language automatically), `{t…}` a phrase translated
  separately, `{s…}` a name or code.
* Prefer accuracy over fluency. Never soften or strengthen the meaning of
  severity levels, confidence, "confirmed", "probable", "suspected",
  "estimate", "forecast" or "scenario", and keep the distinction between
  official figures, model estimates and unverified reports.
* The notice that Ebola Watch is not a medical service, and the fixed sentence
  "Insufficient evidence for a reliable numerical estimate.", must keep their
  full meaning.
* Do not translate "Ebola Watch", "Open Mission of Hope", "R_t", source names
  or citations.
* Use the terms in `_meta.glossary` consistently, and correct the glossary if a
  term is wrong.

## Reviewing a language

1. Edit `frontend/src/i18n/locales/<code>.json` (the GitHub web editor is
   enough) and open a pull request. Note your name or organisation in
   `_meta.reviewed_by` if you want to be credited.
2. CI runs `npm run i18n:check`, which rejects changed or missing placeholders.
3. When a whole catalog has been reviewed, set `reviewed: true` for the
   language in `frontend/src/i18n/index.tsx` and `"status": "reviewed"` in
   `_meta`. The machine-translation notice then disappears for that language.

## Changing or adding text

* Interface text: write it in English in the component with `t("…")` (or
  `<T k="…" />` for sentences containing links), run `npm run i18n:extract`,
  and add translations. Missing translations fall back to English.
* Backend text: when a generated sentence changes, update its template in
  `server.en.json` and the catalogs. `npm run i18n:coverage -- <site>/data`
  lists sentences in a static export (`ebolawatch export-static`) that no
  template matches.
* A new language: add it to `LANGUAGES` in `frontend/src/i18n/index.tsx` (with
  `dir: "rtl"` for right-to-left scripts) and create its catalog.

`npm run i18n:check` prints, for every language, how many interface strings
and backend templates are translated.

## What stays in English

Source titles, citations, licence and access terms, connector status messages,
parameter citations and downloaded files (CSV, JSON, report Markdown). Area
names are shown as officially published; country names follow the reader's
language. The administrative and review screens of the server deployment are
translated with the rest of the interface, but reviewer notes and source
excerpts are shown as written.
